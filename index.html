Interactive modules in emails

Carousels, accordions, hotspots, countdowns, video: all of it can be built into an email, but no client treats it the same way. This guide is here to help you understand what a campaign can actually do, what someone opening the email from Outlook will really see versus Gmail or Apple Mail, and how to build every module so it works everywhere — even when the "wow" effect doesn't fire.

00Introduction

A browser is a single, predictable environment. Inboxes are not: every email client has its own rendering engine, often years old and never designed with interactivity in mind. Outlook desktop for Windows, for instance, doesn't use a browser to draw the HTML at all — it uses the Word engine. Gmail and Outlook.com open the email inside a webview that filters out "risky" CSS and tags. Only Apple Mail (macOS and iOS) is a genuine browser (WebKit), which is why it's almost always the most permissive client.

The result: the same interactive module can look spectacular on an iPhone and be completely invisible on a company PC running Outlook. The golden rule is therefore progressive enhancement — the email has to make sense and be complete even for people who don't see the effect, which becomes a bonus for those who do.

Practical rule: use only one interactive module per email. Combining several components (e.g. carousel + accordion) in the same message increases the risk of CSS inheritance conflicts between them, with unpredictable effects on the final rendering.

"Premium" environments — web browsers (view online) and Apple devices, both desktop and mobile (Apple Mail, Outlook for Mac) — deliver a smooth, complete experience. On Outlook Windows and Android, the message still stays clear and coherent thanks to the fallback images. Hence the advice: talk to whoever analyses the list data to understand how many subscribers use "premium" clients, and design campaigns that genuinely put interactivity to work for that slice of the audience.

Account manager

Never present an interactive module as "guaranteed" to whoever is requesting the campaign (brand, region, e-commerce) without specifying that the experience changes from client to client. It's the first question anyone who's already had a bad surprise in the past will ask.

Designer

Always design the static version (the fallback) first, then add the interactivity as a layer on top. If you start from the effect and try to "add" the fallback afterwards, the fallback almost always ends up broken or incomplete.

03Fallback strategy

The principle is always the same: whoever doesn't support the effect still has to see the core message, not a gap. Two concrete examples — the detail for every module is on its own dedicated page.

Designer

Minimum test before every handoff: a "worst-case" client (Outlook desktop, Word engine) and a "best-case" client (Apple Mail, full WebKit). If the message works at both extremes, it works almost everywhere in between.

"Will the carousel/video/countdown work for all our subscribers?"
No, and that should be said clearly upfront: it will work best for part of the list (typically those on Apple Mail or Gmail) and will show an equivalent static version to everyone else. The static version is still a complete email, not an error.
"Can we know in advance how many people will see the effect?"
Only approximately, starting from the client distribution of their own base (visible in the sending platform's reports). It's not a figure we guarantee — present it as an estimate.
"We want a fillable form/survey inside the email."
Only possible with AMP for Email, and only for people opening from Gmail or Yahoo: everyone else still needs a link to an external page with the same form. It's a more expensive project and should be scoped as such, not as a standard email.
"Why can't we just test it on our own Outlook in the office?"
Because it's almost always the most restrictive client that exists: if an effect "seems to work" there, it will work everywhere; if it "doesn't work" there, that's not a bug — it's the normal fallback to the static version, which still needs to be checked.
