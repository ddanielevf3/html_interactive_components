Animated GIF

universal support
Interactive module · reference sheet

Not "interactivity" in the technical sense, but the most reliable tool for bringing motion to an email: it's an image format, so every client displays it (as long as images are enabled). No risk of a broken fallback.

When to propose it: any time "100% safe" motion is needed, as an alternative to more fragile CSS animations.

Fallback: as with the countdown, no dedicated fallback is needed — it's an image like any other; a descriptive alt is enough.

supportedall major clients — it's technically an image
fallbackno client-specific gap: the only limit is the recipient having images disabled

Additional notes

Best practices for exporting a lightweight, reliable animated GIF — compiled from Litmus's guidance on keeping animated GIFs small in email.

File weight
  • Target under 1MB per GIF — this is the threshold that actually keeps load times fast on mobile data, not just "technically allowed"
  • 5MB is the hard ceiling: heavier files risk being clipped or delayed by webmail clients and blow up total email weight on slow connections
  • Enable transparency where possible — pixels that don't change between frames don't need to be redrawn, which alone can cut file size by a third or more
Why avoid gradients
  • GIF supports a maximum of 256 colors per frame — a smooth gradient needs far more tonal steps than that to render cleanly
  • Without enough dithering, the limited palette can't represent the in-between tones, so gradients render as visible banding (hard stripes instead of a smooth transition)
  • Dithering can hide the banding, but the smoother the gradient needs to look, the higher the dither percentage required — and more dithering means a heavier file
  • Flat, illustration-style color is the safer default: it compresses far better than photography or gradients, which can end up over 20× heavier for the same frame
  • If a photo or gradient is unavoidable, a monochrome color overlay that reduces the palette can cut file size by around 70% versus the untouched original
Other ways to keep the file light
  • Cut between frames instead of fading — fade transitions can make a file up to ~8× heavier because of the extra in-between frames and color blending
  • Drop duplicate or redundant frames, and skip every second (or fourth) frame when converting from video, then compensate by increasing the per-frame delay to keep the original speed
  • Use adaptive color reduction (samples the colors actually dominant in the image) rather than a fixed palette
  • Keep the color table as small as the content allows: roughly 64–128 colors for flat illustrations, 128–256 for photo- or video-derived frames
  • Apply 20–40% lossy compression on export — a small quality trade-off for a meaningfully smaller file

Source: Litmus — "10 Tips for Keeping Animated GIF File Sizes Small".
